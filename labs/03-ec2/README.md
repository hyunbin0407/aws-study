# 3회차 실습: EC2 인스턴스 직접 띄워보기

목표: 키 페어 → 보안 그룹 → 인스턴스 생성 → SSH 접속 → 웹서버 자동 설치까지 EC2의 전체 흐름을 손으로 익힌다.
**반드시 `t2.micro` 또는 `t3.micro`(프리티어 대상)로 진행**하고, 실습이 끝나면 Step 6(정리)까지 마쳐서 과금을 막는다.

## 0. 사전 준비

- [ ] 콘솔 우측 상단 리전을 **서울(ap-northeast-2)**로 설정
- [ ] (권장) Billing 콘솔 → **예산(Budgets)**에서 소액(예: $1) 알림 하나 걸어두면, 실수로 프리티어를 벗어나도 바로 알 수 있음
- [ ] 2회차에서 만든 관리자 계정(`AdministratorAccess`)으로 로그인해서 진행

## Step 1. 키 페어 생성

1. EC2 콘솔 → 왼쪽 메뉴 **네트워크 및 보안 → 키 페어** → **키 페어 생성**
2. 이름: `iam-lab-ec2-key` (편의상 이전 실습과 이름 패턴 통일)
3. 키 페어 유형: **RSA**, 프라이빗 키 파일 형식: **.pem** (macOS/Linux 기준)
4. 생성 클릭 → `iam-lab-ec2-key.pem` 파일이 자동 다운로드됨 (이 파일은 이 시점에만 받을 수 있고, AWS는 따로 보관하지 않음)
5. 터미널에서 다운로드된 파일 권한을 제한 (안 하면 SSH 접속 시 거부됨):
   ```bash
   mv ~/Downloads/iam-lab-ec2-key.pem ~/.ssh/
   chmod 400 ~/.ssh/iam-lab-ec2-key.pem
   ```

## Step 2. 보안 그룹 생성

1. EC2 콘솔 → **보안 그룹** → **보안 그룹 생성**
2. 이름: `iam-lab-ec2-sg`, 설명: 아무거나
3. 인바운드 규칙 추가:
   - 유형 **SSH**, 포트 22, 소스: **내 IP**(My IP) — 콘솔이 자동으로 지금 접속한 IP를 채워줌
   - 유형 **HTTP**, 포트 80, 소스: **Anywhere (0.0.0.0/0)** — 웹서버 테스트를 브라우저로 확인하기 위함
4. 생성

> ⚠️ SSH(22번 포트)를 `0.0.0.0/0`(전체 공개)로 열어두면 전 세계에서 무차별 로그인 시도(브루트포스)가 들어온다. 실습에서도 반드시 "내 IP"로만 제한할 것.

## Step 3. 인스턴스 시작

1. EC2 콘솔 → **인스턴스 시작**
2. 이름: `iam-lab-ec2-instance`
3. AMI: **Amazon Linux 2023** (프리티어 사용 가능 표시 확인)
4. 인스턴스 유형: **t2.micro** 또는 **t3.micro** (프리티어 표시된 것)
5. 키 페어: Step 1에서 만든 `iam-lab-ec2-key` 선택
6. 네트워크 설정에서 **"기존 보안 그룹 선택(Select existing security group)"**을 반드시 선택 → `iam-lab-ec2-sg` 체크
   ⚠️ 기본값이 **"보안 그룹 생성(Create security group)"**으로 되어 있어서, 이걸 놓치면 AWS가 `launch-wizard-N`이라는 새 보안 그룹을 자동으로 만들어 붙인다 (SSH만 있고 HTTP는 없어서 웹서버 접속 시 타임아웃 발생 — 아래 트러블슈팅 표 참고)
7. **고급 세부 정보(Advanced details)** 펼치기 → **사용자 데이터(User data)** 칸에 [`user-data.sh`](user-data.sh) 파일 내용을 그대로 붙여넣기
8. **인스턴스 시작**

인스턴스가 `running` 상태가 되고 상태 검사(Status check)가 2/2 통과할 때까지 1~2분 정도 기다린다.

## Step 4. 웹서버 확인 (User Data가 잘 동작했는지)

1. 인스턴스 목록에서 `iam-lab-ec2-instance` 클릭 → **퍼블릭 IPv4 주소** 복사
2. 브라우저 새 탭에 `http://<퍼블릭IP>` 입력
3. "Hello from EC2!"와 인스턴스 ID, 가용 영역이 표시되면 User Data 스크립트가 정상적으로 실행된 것

안 뜬다면: 인스턴스를 시작한 지 1~2분이 안 지났거나, 보안 그룹에 HTTP(80) 인바운드가 빠졌거나, User Data를 붙여넣지 않고 시작한 경우다. User Data는 재부팅으로는 재실행되지 않으므로, 빠뜨렸다면 인스턴스를 종료 후 다시 만들어야 한다.

## Step 5. SSH 접속 & 인스턴스 상태 체감

1. 터미널에서:
   ```bash
   ssh -i ~/.ssh/iam-lab-ec2-key.pem ec2-user@<퍼블릭IP>
   ```
   처음 접속 시 "known hosts에 추가할지" 물으면 `yes`
2. 접속되면 `httpd` 상태를 직접 확인:
   ```bash
   systemctl status httpd
   ```
3. 접속 종료: `exit`
4. 콘솔에서 인스턴스를 **중지(Stop)** → 다시 **시작(Start)** → **퍼블릭 IP가 바뀌는 것**을 확인 (Elastic IP를 안 붙였기 때문에 매번 새로 할당됨)
5. 바뀐 새 퍼블릭 IP로 다시 SSH 접속이 되는지 확인

## Step 6. 정리 (Clean up) — 꼭 진행

과금을 막기 위해 아래 순서로 정리한다.

1. EC2 콘솔 → 인스턴스 선택 → **인스턴스 상태 → 인스턴스 종료(Terminate)** → 확인
   - 종료 시 기본 옵션대로라면 루트 EBS 볼륨도 같이 삭제된다 (인스턴스 세부 정보의 "스토리지" 탭에서 "종료 시 삭제" 여부 확인 가능)
2. 인스턴스가 `terminated` 상태로 바뀔 때까지 대기 (1분 내외)
3. **보안 그룹 삭제**: `iam-lab-ec2-sg` (인스턴스가 완전히 종료된 후에만 삭제 가능)
4. **키 페어 삭제**: EC2 콘솔 → 키 페어 → `iam-lab-ec2-key` 삭제, 로컬 `.pem` 파일도 필요 없으면 삭제
   ```bash
   rm ~/.ssh/iam-lab-ec2-key.pem
   ```
5. EC2 콘솔 → **볼륨(Volumes)** 메뉴에서 `iam-lab-ec2-instance`에 연결됐던 EBS 볼륨이 같이 삭제됐는지 확인 (남아있으면 수동 삭제 — 방치하면 계속 과금됨)

## 오늘 실습에서 만난 에러 모음 (빠른 참조)

| 증상 | 원인 | 해결 |
|---|---|---|
| 브라우저에서 `http://퍼블릭IP` 접속 시 무한 로딩 후 타임아웃 (SSH는 정상 접속됨) | 인스턴스 시작 시 "기존 보안 그룹 선택"을 안 해서 `iam-lab-ec2-sg` 대신 SSH만 열린 `launch-wizard-N`이 자동으로 붙음 | 인스턴스 선택 → 작업 → 보안 → 보안 그룹 변경 → `iam-lab-ec2-sg` 추가 (재시작 없이 즉시 적용됨) |
| 웹페이지의 Instance ID / AZ 값이 비어서 표시됨 | Amazon Linux 2023은 메타데이터 조회 시 기본적으로 IMDSv2(토큰 기반 인증)를 요구하는데, 토큰 없이 바로 조회하면 빈 값 반환 | `user-data.sh`에서 먼저 토큰을 발급받아 헤더에 실어서 조회 (현재 파일은 이미 수정 반영됨) |
