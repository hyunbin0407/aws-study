# 1회차: 클라우드 컴퓨팅 & AWS 개요

- **날짜**: 2026-09-15
- **주제**: 클라우드 컴퓨팅 개념, 클라우드 서비스 모델(IaaS/PaaS/SaaS), AWS 글로벌 인프라(리전/가용 영역/엣지 로케이션), AWS를 쓰는 이유

## 핵심 개념 요약

### 클라우드 컴퓨팅이란?

서버·스토리지·네트워크·DB 같은 IT 자원을 직접 사서 운영(온프레미스)하는 대신, 인터넷을 통해 **필요한 만큼 빌려 쓰는 것**. AWS 같은 사업자가 전 세계 데이터센터를 잘게 쪼개서 사용한 만큼 과금(pay-as-you-go)한다.

| 특징 | 온프레미스 | 클라우드 |
|---|---|---|
| 초기 비용 | 큰 초기 투자(CapEx) | 초기 투자 거의 없음(OpEx) |
| 확장 속도 | 몇 주~몇 달 | 몇 분 |
| 유지보수 | 직접 하드웨어 관리 | AWS가 관리 |
| 탄력성 | 트래픽 대응 어려움 | Auto Scaling으로 자동 확장/축소 |

핵심 키워드: **탄력성(Elasticity)**, **사용한 만큼 지불(Pay-as-you-go)**

### 클라우드 서비스 모델

- **IaaS**: 인프라(서버/네트워크/스토리지)만 제공, OS 관리는 사용자 몫 — 예: EC2
- **PaaS**: 런타임/개발 환경까지 제공, 코드만 배포 — 예: Elastic Beanstalk
- **SaaS**: 완성된 소프트웨어를 그대로 사용 — 예: Gmail, Slack

### AWS 글로벌 인프라

- **리전(Region)**: 세계 각지에 있는 독립된 지리적 영역 (예: `ap-northeast-2` 서울, `us-east-1` 버지니아 북부)
- **가용 영역(Availability Zone, AZ)**: 하나의 리전 안에서 **물리적으로 완전히 분리된** 데이터센터(단지). 전원/냉각/네트워크가 독립적이며, 서로 전용 회선으로 빠르게 연결됨. 보통 리전당 3개 이상 존재.
- **엣지 로케이션(Edge Location)**: 리전보다 훨씬 많은 도시에 있는 소규모 시설. CloudFront(CDN), Route 53처럼 사용자와 가까운 곳에서 빠르게 응답해야 하는 서비스에 사용.

```
리전 (예: 서울 ap-northeast-2)
 ├── 가용 영역 A (독립된 데이터센터)
 ├── 가용 영역 B
 └── 가용 영역 C

전 세계 곳곳 → 엣지 로케이션 (CDN 캐싱용, 훨씬 더 많은 지점)
```

### AWS를 쓰는 이유

1. 초기 투자 비용 불필요
2. 사용한 만큼만 지불
3. 용량을 미리 예측할 필요 없음
4. 속도와 민첩성 향상 (몇 분 만에 리소스 생성)
5. 데이터센터 운영/유지보수 비용 절감
6. 전 세계 어디든 몇 분 만에 배포 가능

## Q&A로 정리한 포인트

**Q1. 리전과 가용 영역의 차이는?**

처음엔 "리전 = 집, 가용 영역 = 방"으로 이해했는데, 이 비유는 AZ들이 물리적으로 거의 붙어있다는 오해를 줄 수 있어 아래처럼 수정함:

> **리전 = 도시**, **가용 영역 = 그 도시 안에서 서로 다른 지역에 떨어진, 독립된 데이터센터 단지**

같은 리전(도시) 안이라 전용 회선으로 빠르게 통신은 되지만, 전원·냉각·네트워크가 완전히 분리되어 있어서 한 AZ의 장애(정전, 화재 등)가 다른 AZ에 영향을 주지 않는다.

**Q2. 왜 서버를 하나의 가용 영역에만 두면 위험한가?**

처음 답: "데이터가 날아가면 복구가 힘들다" (데이터 유실 관점 — 맞는 지적이지만 일부)

보완한 핵심 개념: **가용성(Availability)** 문제가 더 크다.
- 그 AZ에 장애가 나면 거기 있던 서버가 전부 다운되어 **서비스 자체가 완전히 멈춤(다운타임)**
- 이를 **단일 장애점(SPOF, Single Point of Failure)**이라고 부름
- 그래서 실무에서는 최소 2개 이상의 AZ에 나눠 배포해 하나가 죽어도 서비스가 계속 돌아가게 설계함
- 데이터 손실 방지는 별도로 RDS Multi-AZ, S3 복제 등으로 해결 (추후 회차에서 다룰 예정)

## 헷갈렸던 부분 / 추가로 찾아볼 것

- 리전/가용 영역을 "집-방"처럼 물리적으로 가까운 것으로 오해하기 쉬움 → "도시-독립된 데이터센터" 비유가 더 정확
- 가용성(다운타임 방지)과 내구성(데이터 유실 방지)은 다른 개념 — 각각 어떤 서비스/기능으로 해결하는지는 이후 VPC, RDS, S3 회차에서 자세히 다룰 예정
