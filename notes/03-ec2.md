# 3회차: EC2 (Elastic Compute Cloud)

- **날짜**: 2026-09-23
- **주제**: EC2 핵심 개념(인스턴스/AMI/인스턴스 유형/보안 그룹/키 페어/스토리지), 프리티어, 인스턴스 생명주기, User Data

## 핵심 개념 요약

### EC2란?

**EC2(Elastic Compute Cloud)**는 가상 서버(인스턴스)를 원하는 만큼, 원하는 시간만큼 빌려 쓰는 **IaaS** 서비스. 1회차에서 배운 "IaaS = 인프라만 제공, OS 관리는 사용자 몫"이 그대로 적용되는 대표 서비스다.

### EC2를 구성하는 핵심 요소

| 요소 | 의미 |
|---|---|
| **AMI (Amazon Machine Image)** | 인스턴스를 만들 때 쓰는 "OS + 기본 설정" 템플릿. Amazon Linux, Ubuntu 등. 하나의 AMI로 동일한 서버를 여러 대 복제 가능 |
| **인스턴스 유형 (Instance Type)** | vCPU/메모리/네트워크 성능 조합. 예: `t2.micro`(1 vCPU, 1GiB, 프리티어), `t3.micro`, `m5.large` 등. 앞 글자(t/m/c/r 등)는 용도(범용/컴퓨팅 최적화/메모리 최적화)를 뜻함 |
| **키 페어 (Key Pair)** | 인스턴스에 SSH로 접속하기 위한 공개키/개인키 쌍. 개인키(`.pem`)는 생성 시 한 번만 다운로드 가능, AWS는 보관하지 않음 |
| **보안 그룹 (Security Group)** | 인스턴스 단위로 붙는 방화벽. 기본은 모든 인바운드 차단, 아웃바운드는 전체 허용. **Stateful**이라 나간 트래픽에 대한 응답은 자동으로 허용됨 |
| **스토리지 (EBS)** | 인스턴스에 붙는 네트워크 기반 가상 디스크. 인스턴스를 삭제해도 EBS만 따로 남길 수도 있음 (볼륨의 "종료 시 삭제" 옵션에 따라 다름) |
| **퍼블릭 IP / 탄력적 IP (Elastic IP)** | 기본 퍼블릭 IP는 인스턴스를 stop/start 하면 **바뀐다**. 고정하고 싶으면 별도로 탄력적 IP를 발급받아 연결해야 함 |
| **사용자 데이터 (User Data)** | 인스턴스가 **처음 부팅될 때 한 번** 실행되는 스크립트. 웹서버 설치 같은 초기 설정 자동화에 사용 |

### 인스턴스 생명주기 — Stop vs Terminate

| 상태 | 의미 | 과금 | 데이터 |
|---|---|---|---|
| running | 실행 중 | 인스턴스 시간당 과금 | - |
| stopped | 중지 (전원 끔) | 인스턴스 자체는 과금 안 됨, **EBS 스토리지 비용은 계속 발생** | EBS에 남아있어 유지됨, 재시작 가능 |
| terminated | 종료 (삭제) | 과금 없음 | 기본 설정상 루트 EBS 볼륨도 같이 삭제됨 (복구 불가) |

가장 흔한 실수: "실습 끝났으니 stop 했다" → 사실은 EBS 볼륨 비용이 계속 나가고 있는 상태. 완전히 끝났다면 **terminate**까지 해야 한다.

### 보안 그룹 미리보기 (VPC 회차에서 더 자세히)

- 인바운드 규칙: "어떤 IP에서, 어떤 포트로 들어오는 걸 허용할지" (예: SSH 22번 포트를 내 IP에서만 허용)
- **내 IP를 `0.0.0.0/0`(모든 IP)로 열어두는 것은 실무에서 큰 보안 사고 원인** — 실습에서도 SSH는 반드시 "내 IP"로만 제한

### 프리티어 (Free Tier)

- `t2.micro` 또는 `t3.micro` 인스턴스를 **월 750시간**(사실상 1대를 한 달 내내 켜놔도 무료)까지 12개월간 무료
- 스토리지(EBS)도 30GB까지 무료 범위 존재
- 프리티어 범위를 벗어나거나 다른 인스턴스 유형을 쓰면 바로 과금되므로, 실습에서는 항상 **인스턴스 유형이 `t2.micro`/`t3.micro`인지 확인**하는 습관이 중요

## 헷갈렸던 부분 / 추가로 찾아볼 것

- 인스턴스 시작 시 "기존 보안 그룹 선택"을 놓치면 AWS가 새 보안 그룹(`launch-wizard-N`)을 자동 생성해서 붙임 — 원하는 보안 그룹을 반드시 명시적으로 선택해야 함
- 여러 보안 그룹을 한 인스턴스에 동시에 붙일 수 있고, 규칙은 합집합(Union)으로 평가됨
- Amazon Linux 2023은 메타데이터 조회에 기본적으로 IMDSv2(토큰 기반)를 요구함
- 실습 중 만난 에러/트러블슈팅은 [`labs/03-ec2/README.md`](../labs/03-ec2/README.md) 맨 아래 "오늘 실습에서 만난 에러 모음" 표에 정리해둠
